- No approval is pending. No action remains rejected by automatic approval review. The original backup checkout's Git operation returned permission denied; it was left untouched and work continued in the authorized isolated clone. Network operations/build and headless-browser runs used successful desktop approvals.
- NOT RUN: real Firebase Auth/Firestore emulator integration. A working isolated emulator setup/Java runtime was not available in this checkout. The contract double tests rollback, retries, serialized contenders, read-before-write ordering and write limits, but cannot validate real Firestore contention, indexes or rules evaluation.
- NOT RUN: real-account sign-in, cross-device email consumption, live reminders/cron, photo uploads, destructive project resets/deletion and production mutations. Existing authenticated scripts load local environment values and can mint tokens/write real records; they were not run against production. These require isolated backend data and test-only email infrastructure, or narrowly approved real-account read-only checks.
- NOT VERIFIED: the deployed shared Firebase rules, Vercel CPU quota/billing state, historical August preview failure, and complete browser/device coverage. No paid plan or upgrade was used. No current outage was inferred from historical warnings.
- Bulk operations exceeding one transaction can partially commit if connectivity fails between chunks. Committed child/parent IDs stay coherent, and a retry skips taken portions, but a new HTTP retry can create a second partial group. Reminders/stat recomputation after an interrupted operation are not guaranteed to have run. This is not whole-operation atomicity or exact-once email delivery.
- Aggregate statistics remain best-effort recomputations after primary writes. The audit did not prove exact counter freshness under all concurrent operations. No historical production-data repair was attempted.
- Existing Spanish/French hardcoded English dashboard controls and other pages were not comprehensively translated. New/changed messages are present in all four catalogs. The checks do not establish that every page and flow is fully localized or free of regressions.
- The historical Bava Kamma failure could have depended on a specific old record, session or account. The exact reported real commitment was not mutated. The reproduced current individual/bulk-child rename works; concurrency and error handling were improved independently.
